## 一、高难度选择题

### 1. 答案：**B**

- **解析**：攻击者常通过"攻击链"（attack chain）将多个低危漏洞串联，最终造成高危后果。风险评估必须考虑漏洞组合后的整体风险，这正是威胁建模的价值。
- **易错点**：A、C 都犯了"孤立看漏洞"的错误；低危漏洞在攻击链中可能是关键一环。

### 2. 答案：**B**

- **解析**：Bell-LaPadula 保护**机密性**，核心规则"不上读、不下写"（低级别不能读高级别，高级别不能写低级别，防止泄密）；Biba 保护**完整性**，规则相反"不下读、不上写"（防止低完整性数据污染高完整性数据）。
- **易错点**：两者常被记反。记忆：BLP 管"保密"，Biba 管"完整"。

### 3. 答案：**C**

- **解析**：边界防御失效的主因是**边界模糊**（BYOD/SaaS/多云）、**横向移动**、**内部威胁与凭证泄露**，而非"成本太高无法部署"（边界防御并非因成本而失效）。
- **易错点**：本题问"不包括"，C 是干扰项——成本高是事实但不是边界防御"失效"的核心原因。

### 4. 答案：**B**

- **解析**：Bruce Schneier 的名言："Security is a process, not a product."（安全是过程，不是产品）。安全需要持续投入、监测、响应。
- **易错点**：A 是典型错误认知，也是 Schneier 批判的对象。

### 5. 答案：**C**

- **解析**：安全性必须结合**威胁模型与业务需求**判断。例如：公开新闻网站可接受低机密、高可用；军事系统则相反。脱离场景无法比较"哪个更安全"。
- **易错点**：A、B 都是脱离场景的绝对判断。

## 二、开放/推导题

### 6. 参考答案

**论证思路：**

1. **攻防不对称**：防御者必须保护**所有**入口（面），攻击者只需找到**一个**薄弱点（点）。防御面的规模远大于攻击点，因此防御方在数学上处于劣势。
2. **漏洞的必然存在**：软件/系统由人编写，必然存在缺陷；新功能、新配置会不断引入新漏洞；零日漏洞不可完全预知。
3. **资源有限**：防御者的人力、财力、时间有限，无法覆盖无限多的攻击路径；攻击者却可长期、低成本地试错。
4. **人的不可靠**：即使技术完美，人仍会犯错（点击钓鱼、弱口令）。

**结论**：在"防御所有点 vs 攻击一个点"的不对称下，"绝对安全"逻辑上不可实现。

**最优策略**：追求**相对安全**——① 提高攻击成本、降低攻击收益（让攻击得不偿失）；② 以"Assume Breach"设计检测与响应；③ 纵深防御（多层、多样）；④ 持续过程而非一次性产品。

### 7. 参考答案

**（1）为何 CIA 不足，需 Parkerian Hexad 补充：**

交易场景除机密性、完整性、可用性外，还需要：
- **真实性（Authenticity）**：确保交易请求确实来自真实客户（防伪造身份）。
- **不可否认性（Non-repudiation）**：客户不能否认自己发起过转账（防抵赖）。
- **占有/控制（Possession/Control）**：对密钥、介质等资产的物理/逻辑控制权。

**（2）各要素对应技术手段：**

| 要素 | 技术手段 |
|------|---------|
| 机密性 | TLS 加密、数据库加密、访问控制 |
| 完整性 | 哈希校验、数字签名、事务日志 |
| 可用性 | 双活容灾、负载均衡、离线备份 |
| 真实性 | 多因素认证（MFA）、数字证书 |
| 不可否认性 | 数字签名 + 时间戳、审计日志 |
| 占有/控制 | 硬件安全模块（HSM）、密钥管理 |

## 三、综合思考题

### 8. 参考答案

**错误之处**：把纵深防御理解为"产品堆砌"，忽略了纵深防御是**有机的整体**。

**真正的纵深防御应具备的特征：**
1. **多层（Layered）**：覆盖物理、网络、主机、应用/数据多个层次，单点失守不致命。
2. **多样（Diverse）**：各层用不同技术/厂商，避免同源漏洞"一损俱损"。
3. **冗余（Redundant）**：关键防线有备份。
4. **配合检测与响应**：层与层之间布设监控，攻击者跨层留下痕迹，能被发现并处置。
5. **Assume Breach**：默认会被突破，提前准备响应。

> 要点：简单堆砌产品（如装 3 款杀毒软件）是"同一层的重复"，不是纵深防御。

### 9. 参考答案

**CIA 框架仍适用**，因为 AI/Agent 安全的最终目标仍是保护数据与服务的机密性、完整性、可用性。

**AI/Agent 场景的新威胁映射到 CIA：**
- **机密性**：提示注入窃取系统提示词/训练数据；模型逆向还原训练数据；Agent 泄露内部工具与密钥。
- **完整性**：数据投毒污染训练数据；对抗样本误导模型输出；提示注入篡改 Agent 行为。
- **可用性**：对 LLM 服务的 DoS（大量请求耗尽算力）；越狱使 Agent 拒绝服务或失控。

**传统框架的局限：**
1. CIA 面向"数据与系统"，而 AI 新增了**模型行为安全**（如幻觉、越狱、对齐），难以用 CIA 直接刻画。
2. 需要补充**可解释性、对齐（Alignment）、鲁棒性（Robustness）**等新维度。
3. 攻击面扩展到**供应链**（模型权重、依赖库、数据集、工具插件）。
4. 需要新的威胁建模框架（如 MITRE ATLAS、OWASP LLM Top 10）。
